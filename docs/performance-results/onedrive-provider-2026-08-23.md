The production `megle-onedrive-provider` child is exercised through the framed RPC protocol against an in-process Microsoft Graph emulator. The scenario covers PKCE token redemption, Host Secret Broker create/CAS reverse RPC, AppFolder creation, eight isolated Library namespaces plus root descriptor discovery, immutable matching/conflict behavior, exact and full-body-fallback range downloads, malformed Content-Range, truncated/oversized/corrupt downloads, one-shot 401 refresh, empty and duplicate Delta pages resumed after process restart, 410 cursor reset, 429 Retry-After propagation, quota failure, upload abort, 416 status recovery, ambiguous final 503 reconciliation, a 72 MiB upload split at the frozen 10 MiB boundary, process restart with protected upload-handle recovery, bounded 8 MiB RPC windows with private temp-file downloads, and bearer-token isolation from download/upload capability URLs. The final 2026-08-23 release-mode run completed in 3621 ms on the Windows development host.

Run `npm run bench:onedrive-provider` for the reproducible process benchmark. Run `npm run test:onedrive-live` only with operator-provided `MEGLE_ONEDRIVE_CLIENT_ID` and `MEGLE_ONEDRIVE_LIVE_ACCESS_TOKEN`; live Personal/Business evidence is credential-gated and is not inferred from emulator results.

Docker/Linux reproduction is `docker build -t megle-onedrive-provider .`; the image builds and tests both bundled Provider binaries and installs them read-only below `/opt/megle/plugins`, while `/data` remains data-only. Docker was not installed on the 2026-08-23 Windows host, so Linux execution remains an explicit external evidence gap rather than an inferred pass.
