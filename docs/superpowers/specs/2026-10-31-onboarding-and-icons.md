# Library creation UI and icon system

## Scope

Redesign the first-run and ordinary Library creation surface, keeping Mangoo's existing acrylic/frosted material. Migrate the project's interface glyphs from Lucide to Phosphor through a single curated module. The app logo, media content, persisted Library identity keys and independent external plugin artifacts are unchanged. Later identity artwork requirements are documented in the appearance-popup contract below.

## Creation layout

Use the existing `ModalSurface` and overlay header/body/actions structure. The page is a single form, with a clear title, name, one-or-more material folders, a low-priority Database location disclosure and one primary creation action. The [separated storage contract](2026-11-02-library-storage-separation.md) governs defaults, path provenance and atomic submission. The live colored Library glyph beside the name opens the shared anchored appearance popup in the creation dialog's family. Keep icon/color choices out of the main form. Applying the editor updates the parent draft; cancelling discards only the editor draft. The resulting parent preview state is submitted with creation; display-only fallback text must not become an implicit name. See [the current appearance editor contract](2026-11-01-library-appearance-editor.md).

Keep the initial layout usable at 726×516 without scrolling. At narrower or shorter sizes, allow the body to scroll while actions remain reachable. Long names and directory paths must not displace buttons or overflow the surface. Reuse the shared font, spacing, radius and material tokens. No extra full-window backing plate, local pointer tracking, hover border/fill system or duplicate glow.

Use one integrated identity control with the icon picker inside its left edge and the editable name on the right. The whole row owns one thin boundary and one global pointer highlight; its child input/button do not paint separate frames. Keep the icon's 40px hit target and the name vertically centered in an approximately 58px row. Omit a separate visible name label; retain an accessible input name and the `资源库名称` placeholder. Place any name error below the whole row, preserve its accessibility association and focus/scroll recovery, and do not move the icon when an error appears. The row aligns with the other form sections in normal and compact windows. This integrated row supersedes the earlier separate-label alignment iteration.

Use the Windows typography hierarchy rather than mixed 12/13/14/21px values: title 20px/28px at weight 600; core labels, inputs, paths and errors 14px/20px at weight 400; primary action and appearance-panel heading 14px/20px at weight 600. Do not use 12px semibold for critical form labels. Keep the existing font stack and application scaling; verify computed values, not only declared CSS. Check normal and enlarged rendering without shrinking text to fit a short window. This follows [Microsoft's Windows typography guidance](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/typography) and the Windows ramp in [Fluent typography](https://fluent2.microsoft.design/typography); it does not replace Mangoo's material system.

Remove the welcome subtitle, routine ready/naming footer hints and repeated explanatory paragraphs. Give name/identity and folders visual priority. Use the concise visible labels `文件夹`, `添加` and `数据库`; accessible action names may remain more descriptive. Database defaults normally need no intervention: place a quiet full-width `数据库` disclosure below the folder list, collapsed initially on Desktop and expanded in Web mode where an explicit Core-host path is required. In its collapsed row, keep the label at the left, the current path in lower-contrast single-line ellipsis in the flexible middle, and the chevron at the far right. Preserve the complete path in the tooltip and input value; the label and chevron must not shrink. Opening it exposes the existing editable path and picker in place without repeating the summary path above. Resolver/path and Database validation errors automatically reveal the editor, then focus/scroll recovery targets a visible control. The disclosure retains keyboard, expanded/control association and busy protection; do not add explanatory prose or a separate advanced-settings panel. Each path and its selection/removal actions share one thin row boundary and one global pointer-highlight owner. Use accessible icon actions instead of repeated boxed change buttons. Folder rows emphasize the folder name and retain the complete editable path at the existing 14px/20px input size with lower visual emphasis; never normalize or alter the submitted path for display. Default Files is replaceable, and existing populated folders are valid. Necessary field errors and busy feedback remain, without repeated generic footer instructions. Directory selection alone does not establish validity; show a successful validity state only after authoritative Core validation.

The appearance popup uses the shared anchored glass material/stack and belongs to its parent dialog family. Opening preserves the parent form; Escape cancels the child first and returns focus to its trigger. Tab navigation stays with the active child layer while unrelated modal focus protection remains intact. Keep one registered focus owner, and prevent pending dismissal before the overlay registry removes any part of its family.

## Interaction and lifecycle contract

- Name, icon and color remain ordinary Library metadata. Preserve all sixteen stored icon keys and existing color choices. The 2026-11-01 follow-up adds pure white as the default/reset color while retaining explicitly saved colors; see [switcher and safe registration](2026-11-01-library-switcher-and-registration.md).
- Disable creation until a trimmed name, Database path and at least one content path exist in the draft, and while picking or creating. Paths may be planned and not yet on disk; Core owns validation/creation. Retain defensive submit validation and the synchronous pending guard.
- A cancelled directory picker retains the previous path. Responses from a prior dialog generation must not overwrite a reopened or unmounted form.
- Submit preflights the entire name/Database/content plan, then creates using non-null `normalizedDatabasePath`, `normalizedContentRoots` and `preflightToken`, with `activate: true` and `initialMode: "local-only"`. Never publish a Library and add its initial folders in later requests.
- Freeze the name, picker, appearance choices and dismiss actions during pending operations. Busy/error messages are accessible and placed with the relevant field/action.
- A rejected preflight never calls create. Known reasons receive concise recovery guidance; preserve unknown-error fallback and the existing failure callback.
- Failures retain the draft and permit retry. Successful creation invokes the existing refresh/close flow. Reopening retains the existing draft behavior.
- Enter submits once; Tab navigation, initial name focus and launcher focus restoration remain supported. Preserve ordinary cancel and existing non-busy Escape/outside-dismiss behavior.
- Creation must not bypass the active-Library admission boundary or reintroduce pre-activation catalog requests.
- An activating creation must notify the shared context lifecycle so active title and catalog consumers re-read authoritative Host state. Cover first-run and secondary-window creation, failure and overlapping operations. Do not patch only the Wizard with a synthetic ready event or activate the same Library twice.

The shared renderer adapter owns mutation notifications. Activating creation (including an omitted `activate`) and switching publish the existing `starting-core` teardown signal without restarting Core; a local pending count delays `loading-media` reconciliation until all local mutations settle. Failures also reconcile authoritative state. Nonactivating creation leaves the active context alone. Creation with failed requested activation reports that the Library was created but could not be opened, preserves the Core cause, and directs recovery through the Library list.

Other same-origin renderers receive only a settlement invalidation through the Core-endpoint-scoped `mangoo-library-context:${baseUrl}` BroadcastChannel, using the literal `context-settled` message. They defer reconciliation during their own pending mutations. Do not introduce remote pending leases: a departed publisher must not leave another renderer permanently blocked. This notification does not guarantee recovery when a publisher exits after Core commits but before sending the message; Core context fences still govern requests.

## Icon module contract

`apps/web/src/design/icons.ts` owns curated semantic exports backed by real `@phosphor-icons/react` glyphs. Keep imports explicit and inspectable, with a project-owned icon type and stable SVG size/currentColor/accessibility/ref behavior. The confirmed direction is line icons with filled selected states: use Phosphor `fill` for active layout choices and selected ratings, retaining readable regular line glyphs at small sizes and light weight for large file artwork. Stroke-width overrides from Lucide must be translated to Phosphor weights. Selection fill is an icon state, not a new hover background or border system.

Library identity artwork is the later user-approved exception: a locally bundled Fluent identity collection with dedicated flat-skeuomorphic presentation and custom colors, governed by the appearance-popup contract. General command glyphs retain this Phosphor module. The four layout modes remain visually distinguishable. Existing Library `icon` strings and plugin glyph identifiers continue resolving without migration. Unknown identifiers still use the shared fallback.

Remove the Lucide dependency and all active imports after migration. Historical documents may retain historical references. Do not import the entire icon catalog through an object/namespace lookup. Verify final Web and SDK bundles: SDK design components must remain self-contained, with no undeclared third-party runtime or declaration dependency.

## Acceptance evidence

Test the mounted form through empty, ready, picker cancellation, invalid name/directory, preflight rejection, normalized successful payload, failure/retry, duplicate submission, busy appearance/dismiss locking, stale-result fencing and keyboard/focus transitions. Check long-path and narrow/short-window geometry.

Verify the global icon migration with import/dependency inventory, stable-key mapping coverage, build sizes, shared dropdown/SDK output, representative main/secondary windows and all layout controls. Run the Web, Desktop, UI-design and SDK checks, plus the broad project gate for the project-wide migration.

Retain renderer captures for layout/state and a separate scoped OS-composited capture for preserved behind-window glass. `webContents.capturePage`/CDP cannot establish OS acrylic behavior; capture method, isolated profile/window and boundaries must be recorded. A passing older harness does not substitute for the current surface.
